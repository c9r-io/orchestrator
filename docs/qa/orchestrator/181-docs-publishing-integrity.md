# Orchestrator - Docs Publishing Single Source And Link Integrity

**Module**: Governance / Documentation site
**Scope**: the declared publish set, generator/policy agreement in both directions, navigation
reachability, the untracking of 36 hand-maintained site pages, and relative-link resolution across
every tracked markdown file
**Scenarios**: 5
**Priority**: High

## Background

`scripts/sync-docs.mjs` generated `site/{en,zh}/guide/**` and those directories were gitignored.
`site/{en,zh}/showcases/**` was 36 tracked files with no generator and no upstream. One source —
`docs/showcases/streaming-mark-done-convergence.md`, which
`scripts/qa/test-agent-driver-documentation-alignment.sh` governs and both CEL guides point
readers to — had no published page at all.

FR-131 proposed gitignoring the showcase pages. `site/en/showcases/` held the only English
showcase text in the repository, so doing that first would have deleted 17 translations. The
sources were recovered before anything was untracked, which is what Scenario 4 is evidence for.

**Self-referential safety.** These scenarios read this repository's own documentation and run its
own generator. Every gate invocation writes only into `$TMPDIR`: the publishing gate syncs through
`SYNC_DOCS_DEST` and never touches `site/`, and the link gate builds a synthetic corpus rather
than copying 567 files. No scenario starts a daemon, touches the runtime database, or invokes a
provider binary. Scenario 1 runs `npx vitepress build`, which writes only `site/.vitepress/dist`
(gitignored) and `site/{en,zh}/{guide,showcases}` via the sync, which are generated by definition.

Primary entry points:

```bash
./scripts/qa/test-docs-publishing-integrity.sh
./scripts/qa/test-docs-publishing-integrity.sh --fixture-test
./scripts/qa/test-markdown-link-integrity.sh
./scripts/qa/test-markdown-link-integrity.sh --fixture-test
```

See [DD-143](../../design_doc/orchestrator/143-docs-publishing-integrity.md).

## Scenario 1: The Declared Publish Set Is Produced, And The Missing Showcase Is On The Site

This is the scenario the FR was filed for. Steps 5 to 8 read the built output rather than the
gate, so a bug in the gate cannot make them pass.

### Preconditions

- `jq`, `git`, and `node` are installed; `site/node_modules` present (`cd site && npm ci`).
- Clean worktree.

### Steps

1. `./scripts/qa/test-docs-publishing-integrity.sh`
2. `jq -r '.collections[] | "\(.name): \(.sources | keys | join(", "))"' config/governance/docs-publishing.json`
3. `jq -r '.translationGaps[] | "\(.slug) absent=\(.absentSource) owed=\(.owedTranslation)"' config/governance/docs-publishing.json`
4. Derive the publish set without the gate and compare it to a fresh sync:

```bash
D=$(mktemp -d); SYNC_DOCS_DEST="$D" node scripts/sync-docs.mjs
for c in guide showcases; do for l in en zh; do
  echo "$c/$l: $(ls -1 "$D/site/$l/$c" | wc -l)"
done; done
rm -rf "$D"
```

5. `node scripts/sync-docs.mjs && (cd site && npx vitepress build)`
6. `ls site/.vitepress/dist/{en,zh}/showcases/streaming-mark-done-convergence.html`
7. `rg -n 'streaming-mark-done-convergence' site/.vitepress/config.ts`
8. `rg -n 'docs/showcases/streaming-mark-done-convergence' docs/guide/04-cel-prehooks.md docs/guide/zh/04-cel-prehooks.md`
9. `./scripts/qa/test-agent-driver-documentation-alignment.sh`

### Expected result

- Step 1 exits `0` and reports `7 passed, 0 failed`, with `gaps: 2 declared`.
- Step 2 prints `guide: en, zh` and `showcases: en, zh`.
- Step 3 prints exactly two lines: `full-qa-execution absent=zh owed=en` and
  `streaming-mark-done-convergence absent=zh owed=zh`.
- Step 4 prints `guide/en: 16`, `guide/zh: 11`, `showcases/en: 19`, `showcases/zh: 19`, and the
  sync reports `Synced 65 files (2 from a declared translation gap)`. Both showcase locales carry
  19 pages, including the two declared gaps served from the locale that has them.
- Step 5 completes; the build reports `build complete`.
- Step 6 lists **both** files. Compare against the baseline above, where neither existed.
- Step 7 shows two sidebar entries, one per locale. A page with no entry is published and
  unreachable, which is what Scenario 2's fixture 8 gates.
- Step 8 still shows both guides naming the showcase — the reference is an inline code span, not
  a markdown link, which is why no link checker would ever have caught its absence from the site.
- Step 9 passes: the showcase kept its path, so the FR-126 alignment gate that requires the EN/ZH
  CEL guides to resolve to it and requires its content to carry `claude/cli`, `driver_tool_use`,
  `driver_tool_result` and `driver_terminal` is unaffected.

## Scenario 3: The Link Gate Finds The One Broken Link And None Of The Eight Valid Ones

The negative fixtures are the easy half. The positive controls are the assertion: FR-131's own
list of "three broken links" is what a checker without these rules produces.

### Preconditions

- `jq`, `git`, and `awk` are installed.

### Steps

1. `./scripts/qa/test-markdown-link-integrity.sh`
2. `./scripts/qa/test-markdown-link-integrity.sh --fixture-test`
3. Confirm the two links FR-131 called broken are untouched and unreported:

```bash
rg -n 'resource-model.md' docs/qa/orchestrator/125b-documentation-site-advanced.md
rg -n 'page-2026-02-14T19-22-42-679Z' .claude/skills/playwright-cli/SKILL.md
```

4. `rg -n 'resource_limits' core/README.md`
5. `jq -r '.exemptions | length' config/governance/markdown-links.json`

### Expected result

- Step 1 exits `0` and reports `2 passed, 0 failed` over `567 tracked markdown files` and
  `331 inline link targets outside code spans and fenced blocks`. Before the fix it reported
  `core/README.md:48 links 'core/src/runner.rs', which does not resolve`.
- Step 2 exits `0` and reports `13 passed, 0 failed`, including a positive control covering site
  routes, anchors, anchors on real files, extensionless siblings, plain directories, symlinked
  directories, link titles, angle-bracketed targets, query strings, single-backtick code spans,
  double-backtick spans, and ``` and `~~~` fences — and three negative fixtures: a missing
  target, a missing target behind an anchor, and a repo-relative path used where a file-relative
  one belongs, which is `core/README.md`'s actual defect.
- Step 3 shows both still present and unchanged. They are a code span and a fenced block; they
  were never links, and "fixing" them would have been damage.
- Step 4 shows the repaired link pointing at
  `../crates/orchestrator-runner/src/runner/resource_limits.rs`, which is where the `setrlimit`

- Step 5 prints `0`.

## Scenario 4: The 36 Tracked Pages Became Generated Output Without Losing What They Served

### Preconditions

- Clean worktree.

### Steps

1. `git ls-files site/en/showcases site/zh/showcases | wc -l`
2. `rg -n 'site/en/showcases|site/zh/showcases' .gitignore`
3. `ls -1 site/en/showcases/*.md | wc -l`
4. `./scripts/qa-doc-lint.sh` — or `./scripts/qa-doc-lint.sh`
5. Confirm both showcase source locales are in the language they claim:

```bash
for f in docs/showcases/zh/*.md; do
  n=$(perl -CSD -ne 'BEGIN{$c=0} $c++ while /\p{Han}/g; END{print $c}' "$f")
  [ "$n" -lt 50 ] && echo "NOT CHINESE: $f"
done
```

6. `rg -c '插件策略治理' docs/showcases/zh/webhook-integration.md`

### Expected result

- Step 1 prints `0`; step 2 shows both directories ignored; step 3 prints `19` — present on disk,
  generated, untracked, exactly as the guide pages already were.
- Step 4 prints `PASS`. Its narrower "site guide files must not be tracked" assertion was removed
  in favour of `check_generated_not_tracked`, which reads the collections from the policy instead
  of naming two paths; both run in the same `governance` job.
- Step 5 prints nothing. This check is not decorative: the recovery initially wrote English into
  `docs/showcases/zh/orchestrator-usage-manual-testing.md`, because that file's repository source
  was *already* English and the only Chinese copy lived in `site/zh/showcases/` — which was about
  to become generated output.
- Step 6 prints `1`. The Plugin Policy Governance section existed only in the tracked `site/zh`
  page and was ported back to its source before the untracking, so regenerating does not drop it.

### Per-object comparison

Each of the 36 tracked pages compared individually against its generated replacement, recorded
before removal:

| Pages | Difference |
|---|---|
| 13 | byte-identical |
| 19 | link form only (`/zh/showcases/qa-loop` → `./qa-loop.md`; `](fr-watch)` → `](./fr-watch.md)`), zero prose lines |
| 4 (zh) | prose differs: `benchmark-multi-model-execution`, `self-bootstrap-execution-template`, `self-evolution-execution-template`, `webhook-integration` |

Every prose difference in those four was inspected line by line. In each case the **source is
newer** — the benchmark matrix had been updated to the C1/D1/E1 combinations, two files had
gained "historical execution log, if still retained" qualifiers, and `webhook-integration` had
gained an FR-099 Slack source note and expanded manifest examples — except the one section noted
in step 6, which was ported back. No line the site served is dropped.

The generated ZH pages do lose the hand-translated *link text* (`[Quick Start]` had been
rewritten to `[快速开始]`). A generator cannot reproduce that; the alternative is hand-maintained
pages, which is the defect.

### Reverse-applicable removal evidence

The untracking is `git rm -r --cached site/en/showcases site/zh/showcases` inside commit
`b9ca2bc6`, which touches only index removals plus the recovered sources. `git revert b9ca2bc6`
restores all 36 files byte-for-byte from history; no build step or generated artifact stands
between the commit and its inverse.

## Scenario 5: The Gates Are Actually Enforced, And Their Tooling Is Present Where They Run

### Preconditions

- `jq` and `rg` are installed.

### Steps

1. `./scripts/qa/test-qa-gate-surface.sh`
2. `jq '.scripts[] | select(.path | test("docs-publishing|markdown-link"))' config/governance/qa-gate-surface.json`
3. `rg -n 'test-docs-publishing-integrity|test-markdown-link-integrity' .github/workflows/ci.yml`
4. `rg -n 'setup-node' -A 3 .github/workflows/ci.yml`
5. `rg -n 'paths:' -A 6 .github/workflows/docs.yml`
6. `rg -n 'test-docs-publishing-integrity' .github/workflows/docs.yml`

### Expected result

- Step 1 exits `0`, reports `5 passed, 0 failed`, and `18 of 51 gates are ci-required`. Its
  `check_wiring_truth` is what proves step 2's claim is more than written down.
- Step 2 shows both entries as `ci-required`, `job: governance`, `providerIsolation.mode:
  no-provider`.
- Step 3 shows four steps: each gate plus its fixture run.
- Step 4 shows `actions/setup-node` in the `governance` job. Without it the publishing gate exits
  on its own missing-command preamble — FR-134's hazard of a gate whose tooling is absent from
  the job it claims to run in.
- Step 5 shows `docs/showcases/**`, `scripts/sync-docs.mjs`, and
  `config/governance/docs-publishing.json` added to the deploy trigger. Before this, a
  `docs/showcases/**` change matched no path and could never reach the site.
- Step 6 shows the publishing gate running before the site build, so a drift fails the deploy
  rather than shipping.
