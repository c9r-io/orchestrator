# Reset Local Environment

Reset is destructive. Resolve the exact state boundary first and preserve unrelated projects, tickets, and in-flight tasks.

## Agent Orchestrator Repository

This repository has no Docker Compose reset contract. For isolated QA state, prefer the product-owned project boundary:

```bash
orchestrator delete project/<project> --force
orchestrator apply -f fixtures/manifests/bundles/<fixture>.yaml --project <project>
```

Before deletion, list tasks for the target project and confirm the project name. Do not delete `~/.orchestratord/`, its SQLite database, or tracked files in `docs/ticket/` as a routine reset.

If the database is missing, `orchestrator init` creates runtime state. It is not a reset command.

## Generated Project Docker Branch

Only a target generated by `project-bootstrap` is expected to carry `scripts/reset-docker.sh` and `docker/docker-compose.yml`. Require both paths and preview the script before running it:

```bash
test -x scripts/reset-docker.sh
test -f docker/docker-compose.yml
sed -n '1,240p' scripts/reset-docker.sh
```

Then state explicitly that containers, project images, and volumes will be replaced. Run the repository-owned script only after the user-authorized target and data loss boundary are clear.
