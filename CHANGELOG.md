## [Unreleased]

### Fixed
- **`-o json` and `-o yaml` no longer return different data from the same command** (FR-154) — six commands maintained two hand-written projections that had silently diverged: `task list` yaml dropped all three item counters, `task items` yaml dropped `fix_required`/`fixed`/`last_error`/`started_at`/`completed_at`, `event list` yaml dropped `task_item_id` and renamed+re-typed `payload` (parsed object) to `payload_json` (raw string), `agent session list/get/resolve` yaml was hand-interpolated pseudo-YAML dropping 12 of 17 fields and producing invalid YAML for values containing `: `, `agent list` yaml printed capabilities via `{:?}` and omitted keys conditionally, and `attention get`/`follow` `-o table` printed compact JSON. Every printer now builds exactly one `serde_json::Value` and serializes it through `output/render.rs`, the crate's single serialization site; a serialization failure is now a stderr diagnostic and a nonzero exit instead of a silently printed empty string (16 `unwrap_or_default()` sites deleted). Both encodings of every payload are proven deep-equal over fully-populated fixtures by the `format_parity` test suite, whose comparator is itself proven fallible, and `chokepoint_no_stray_serializers` fails the build on any reintroduced out-of-chokepoint serializer, per-encoding match arm, or swallowed serialization error
- **`db`, `qa doctor`, and `secret key` commands accept the `-o yaml` they advertise** (FR-154) — clap offered `yaml` in six commands whose handlers then rejected it with a runtime error; the shared projection made yaml free, so the bails are deleted. `handoff`/`source` `-o table` render a real key/value table instead of silently printing yaml
- **The v0.5.0 release page shipped three GUI checksums without their binaries** (FR-076 closure) — the publish job's glob list (`dist/*.tar.gz`, `dist/*sha256*`) predated the `gui-build` job: the `.sha256` files matched `*sha256*` while the `.dmg`/`.AppImage`/`.deb` they described matched nothing, so a green publish job attached checksums for absent files. Closed on the release itself by uploading the same run's checksum-verified artifacts; closed structurally by adding the binary globs and `check_gui_asset_globs` to `scripts/qa/test-release-publish-surface.sh`, which derives the staged artifact set from the gui-build staging step and requires a covering publish glob for each artifact and its checksum (fixture 6 comments out `dist/*.dmg`; the check also reproduces the defect verbatim against the release.yml recorded at the v0.5.0 tag). The staged set and the published set were two enumerations of one surface that nothing compared — §4.4 shape 2 in release tooling
- **crates.io Trusted Publishing stopped at 5 of 12 crates** (FR-076 closure, recorded) — the v0.5.0 crates-io job published proto, config, collab, security and runner, then got `403: token not valid for crate orchestrator-persistence`; the remaining seven were published with the local token from the exact tag commit (the FR-151 bootstrap precedent). The per-crate Trusted Publishing configurations for the other seven are a crate-owner web-UI action, recorded in DD-166's known limits

### Changed
- **One output convention: `-o {table,json,yaml}` everywhere, with two named exceptions** (FR-154) — `version` and `task trace` gain `-o` (their `--json` flags become hidden aliases for one release cycle, see Compatibility); `attention claim/snooze/resolve/action`, `source ingest/bind`, `source binding suspend/resume`, and eleven `source connection` mutations gain the `-o` flag they lacked (default yaml — previously the format was hardcoded). Streaming commands (`attention follow`, `source automation watch`, `source connection watch`) take `-o {json,yaml}` via a stream-only format enum: json means one compact document per line (NDJSON), and the `table` choice that silently printed JSON is no longer advertised. The two deliberate exceptions, kept because they are not data encodings: `agent session read --chunks-json` (a content/framing mode) and `guide --format {markdown,json}` (document rendering). Default convention: collections → `table`, single objects and mutation acks → `yaml`, streams → `json`; kubectl-style `get` (collection, table) vs `describe` (detail, yaml) stay distinct by that rule

### Compatibility And Migrations
- **`--json` on `version` and `task trace` is deprecated** (FR-154) — both flags still work this release cycle as hidden aliases of `-o json` (they conflict with an explicit `-o`), and will be removed in the release after next. Migrate to `-o json`; `scripts/regression/scenarios/probe-low-output.sh` already has
- **`task trace -o json` (and `--json`) now prints pretty-printed JSON** (FR-154) — previously the server's `trace_json` string was echoed verbatim (compact); the data is identical and `jq` consumers are unaffected, byte-level comparisons are not
- **`task items -o json` renames `label` to `qa_file_path`** (FR-154) — json/yaml now share the projection `task info` uses; the value is unchanged, and both encodings additionally gain `task_id`, `ticket_files`, `ticket_content_json`, `updated_at`. No in-repo consumer read `.label`
- **`task list` and `event list` json/yaml carry the full projection** (FR-154) — `task list` gains `project_id`/`workspace_id`/`workflow_id`/`parent_task_id`/`spawn_reason`/`spawn_depth`/`created_at`/`updated_at` in both encodings (yaml additionally regains the three item counters it dropped); `event list` json gains `task_id`, and its yaml `payload_json` string is now `payload`, a parsed object, matching json. Additive except the `payload_json` rename, which yaml consumers must rename
- **`agent session get`/`resolve` default output flips table → yaml** (FR-154) — the single-object convention; every in-repo consumer passes `-o json` explicitly. `agent session list` keeps its table default. `agent session` yaml is now real YAML carrying all 17 json fields
- **Streaming `-o table` is rejected at parse time** (FR-154) — `attention follow -o table` and `source automation watch -o table` previously printed compact JSON while claiming to be a table; the option is gone from `--help` and the parser. `source connection watch` output changes from pretty JSON blocks to NDJSON (one compact document per line) and gains `-o yaml`
- **`attention get -o json`/`attention list -o json` are now pretty-printed** (FR-154) — previously compact single-line JSON; `jq` consumers unaffected

### Compatibility And Migrations
- Migrations 27-32 add Attention/change feeds, handoff/resume state, Session control fencing, source events/bindings, canonical action audit, and Process Console metric observations/rollups. They are additive apart from migration 29 relabeling the terminal Session state `exited` to `closed`, forward-only, restart-safe, and preserve existing task and Session identity.
- Migrations 33-34 add durable source automation routes, frozen template/binding generations, optimistic route versions, bounded retry leases, attempt/change history, and Attention correlation. They are additive except that migration 34 remaps in-flight route statuses to the new vocabulary (`reserved`→`matched`, `rendering`→`rendered`, `completed`→`routed`), and forward-only; normal binary rollback keeps their tables and disables reaction writers before using a verified compatible binary.
- Daemon migration 35 adds SourceConnection, OAuth intent, and monotonic connection-change persistence. Slack Gateway schema versions 1-2 independently add encrypted app/install credentials, normalized delivery/audit state, and target-side transfer handoffs. Both stores are additive, forward-only, and backed up/restored with their own encryption keys.
- Daemon migration 36 adds safe dedicated App projections and provisioning checkpoints. Slack Gateway schema 3 adds per-App encryption contexts, one-time import capabilities, signed receipt metadata, dedicated OAuth identity, and exact event endpoint mapping; populated shared/manual state remains compatible.
- Daemon migration 37 adds reviewed dedicated-provisioning migration targets. Slack Gateway schema 4 adds installation/version/source-mode OAuth fences so stale or unreviewed App-mode callbacks fail closed; older binaries reject newer stores rather than guessing rollback compatibility.
- **Breaking (manifests): `runner.executor: streaming` is rejected.** The field remains in the public RuntimePolicy schema as a parse-only compatibility field; `shell` is accepted solely for round-trip compatibility, and `streaming` fails Apply with `[legacy_runner_executor_removed]`. Configure provider execution on the Agent via `spec.driver` (`shell/cli`, `claude/cli`, or `codex/cli`) instead.
- Agent manifests that still carry `spec.command` without `spec.driver` remain accepted during the compatibility window: Apply emits `[legacy_agent_command_deprecated]` and persists the Agent as `shell/cli`, preserving the command, sandbox, prompt-delivery, `command_rules`, and TTY semantics. The scheduler has no non-driver Agent branch left and fails closed with `[legacy_agent_execution_removed]`. Rollback is a reviewed explicit `shell/cli` Agent, not a legacy executor.
- Workflow manifests authored with legacy capture or JSONPath post-action coordination are rejected at Apply with `[legacy_coordination_removed]` and `[legacy_json_path_removed]` before a task can run.
- Existing task, trace, log, watch, CLI, and additive gRPC clients remain compatible, and no database migration is required for the execution changes above. No persisted `Task` rename or destructive schema conversion is included.
- No database migration is required for task workspaces. Existing Workspace manifests remain compatible through the default `code_repo` kind and `root_path` input alias; exported manifests use `work_dir`.
- Normal rollback disables source/session/resume writers and optional projectors before deploying the previous binaries; it retains all applied migrations (27-37) and all Console tables. Database restore is reserved for migration failure or corruption.

### Slack Permissions, Secrets, And Privacy
- Slack Events API configuration requires `reaction_added` delivery and the `reactions:read` scope. Inbound requests use Slack Signing Secret verification; outbound `chat.getPermalink` uses a separately referenced installation token from SecretStore.
- Slack message bodies, attachments, and thread transcripts are not ingested. Tasks contain the configured Skill invocation plus the protected message permalink; safe source/route/UI projections omit credentials, raw payloads, rendered goals, and permalinks unless an Operator explicitly opens the protected route.
- Managed shared mode keeps official app and installation tokens encrypted only in the Slack Gateway. The daemon holds an encrypted installation-scoped pairing; OAuth state/code, tokens, raw Slack bodies, private workspace names, and provider URLs are excluded from safe connection projections, browser storage, tasks, metrics, and routine logs.
- Dedicated mode keeps the Configuration Token only in zeroizing daemon memory and clears it before UI review completes. Newly created App credentials move once into connection-context encrypted Gateway storage; safe state exposes only digests, manifest version, and stable provisioning errors.

### Known Non-goals
- **`x86_64-unknown-linux-musl` is a portability proof, not a shipped target** (FR-150) — the cross-compile gate keeps glibc-only code from landing; release.yml deliberately publishes no musl artifact and install.sh does not offer one. Recorded here so the gate-set/ship-set difference reads as a decision rather than an oversight; `scripts/qa/test-release-publish-surface.sh` asserts the shipped set, and this entry is the exemption's written reason. Intel macOS (`x86_64-apple-darwin`) is likewise out of the shipped set by decision, with a behavioral refusal in install.sh and the formula rather than a silent 404 (see Fixed).
- **Retention cleanup and `task delete` cannot remove a task that used handoff, resume or source ingest** — found while closing FR-142, deliberately not fixed by it. `task_cleanup.rs` (the `retentionDays` sweep) and `delete_task_impl` (the operator's explicit `orchestrator task delete`) both route through `task_repository`'s cascade, which clears one of the eight references that can refuse a delete. For a task carrying a `handoff_snapshots`, `resume_plans`, `resume_executions`, `source_bindings`, `source_events`, `source_routing_attempts` or `source_automation_routes` row, the delete fails with `FOREIGN KEY constraint failed` — reproduced against that exact statement sequence. FR-142 characterised this path as "the correct one"; that is withdrawn, and recorded here rather than left to be rediscovered. Extending the cascade changes what an explicit `task delete` destroys and needs its own decision, which FR-142's skip logging is designed to inform. See [DD-150](docs/design_doc/orchestrator/150-trigger-history-limit-cascade.md) known limits.
- Desktop application packaging/distribution (FR-076), hosted multi-tenant SaaS, down migrations, arbitrary checkpoint rollback, and unreviewed non-idempotent replay are not part of Console v1.
- Marketplace distribution, Enterprise Grid/GovSlack, outbound Slack progress messages, `reaction_removed` task cancellation, message-body ingestion, production Slack release testing, in-place Slack Signing/Client Secret rotation, and destructive automation down migrations are not included. FR-114/FR-115 live certification is limited to a controlled non-production Slack sandbox.

### Added

#### Core Engine
- DAG execution engine with topological sort, cycle detection, and conditional edges

- Client/server model: `orchestratord` daemon + `orchestrator` CLI over gRPC/UDS

- Declarative YAML manifests (v2 resource model: `orchestrator.dev/v2`)

- Repeatable steps with per-cycle execution control
- Step templates for reusable step definitions
- Item-scoped git worktree isolation for parallel execution

- mTLS control plane with auto-generated PKI (CA, server, client certificates)

- SecretStore encryption (AES-256-GCM-SIV) with key rotation support
- Control plane audit logging
- Sandbox enforcement: resource limits, network isolation, writable paths

- Event system with TTL cleanup and JSONL archival
